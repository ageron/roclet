# M2 — Local reactive editing

Open `/web/edit.html`. Roclet adds cell editing to the same Roc core and WASM
compiler used by the format playground. It introduces no Node/npm dependency,
frontend framework, bundler, CDN, or external service.

## What is implemented

- Code and Markdown cells, insertion, deletion, movement, collapse, and explicit
  kind changes. A code cell containing only comments stays code while editing.
- Notebook and complete editable-source views, Roc/Markdown switching, generated
  Roc preview, undo/redo, and keyboard shortcuts (Cmd/Ctrl+Enter to run a cell,
  Cmd/Ctrl+Z to undo, Cmd/Ctrl+S to download).
- Automatic evaluation after a short pause, manual Run Cell/Run All, and Stop.
  Editing invalidates results immediately while keeping their previous display
  visible in gray with a small spinner until a new result replaces it. Stop terminates the worker and pauses
  automatic execution; enabling Auto-run resumes it.
- Per-cell text results and inferred types, ordered inline debug transcripts,
  structured diagnostics, and safe Markdown rendering.
- Transactional IndexedDB autosave, recovery on reopening, a recent-documents
  library, new documents, `.roc`/`.md` upload, and explicit downloads. A download
  is a separate copy, not a write back to the imported file.

Undo retains up to 100 edit groups, bounded to approximately 4 MiB, in this tab.
Cell keys remain browser-only and never become random IDs in exported source.
Autosave records the editable cells even when their combined source is malformed.
The save label changes to **Saved in this browser** only after the IndexedDB
transaction completes. Storage errors remain visible and a downloaded backup is
available. Autosave does not include live results or debug transcripts.

## Notebook interaction

The document bar keeps the title, File menu, Auto-run and Run all visible. File
contains new/open/download and recent documents. The `•••` notebook menu holds
source view, file format, undo/redo, runnable Roc and shortcut help. Stop appears
while a worker operation is in progress. Save failures remain visible.

Cells have no permanent header. Hover, keyboard focus or the current selection
reveals Run and a `⋯` menu for kind, movement, collapse and deletion. On touch
screens these controls stay visible. Insertion controls appear in every gap,
including before the first cell; the final insertion controls remain visible.
They also appear on keyboard focus.
The hover area includes the entire rectangle containing the cell and its action
buttons. Menu headings use the same visible cell number as the gutter; inferred
output IDs are labeled separately as `id=…`.

Click Markdown to edit its source (links remain links). Cmd/Ctrl+Enter renders
it and selects the cell. Esc also leaves text editing. Rendered Markdown is
retained across unrelated edits and unchanged Markdown does not discard current
code results when rendered again.

| Shortcut | Behavior |
| --- | --- |
| Esc | Select the current whole cell |
| Enter | Edit the selected cell |
| Up / Down | Select the previous / next cell |
| Shift+Up / Down | Extend or shrink a contiguous cell selection |
| Cmd/Ctrl+A | Select all editable cells in cell selection mode |
| Cmd/Ctrl+C / X / V | Copy / cut / paste whole cells in cell selection mode |
| A / B | Insert a code cell above / below the selection |
| Delete / Backspace | Delete selected cells; undo restores them |
| Cmd/Ctrl+Enter | Run the current code cell or render Markdown |
| Shift+Enter | Run/render, then select the next cell; append if at the end |
| Alt+Enter | Insert and edit a cell below, then run/render the previous cell |
| Cmd/Ctrl+Z / Shift+Z | Undo / redo |
| Cmd/Ctrl+S | Download a copy |
| ? | Open shortcut help while selecting cells |

Click a cell number to select it, or Shift-click to extend a range. Selection is
browser-only and follows cell keys across movement. Generated cells are excluded.
The cell menu applies movement, collapse/expand and merge to the selected range
when opened on a selected cell. Merging code comments out the compiler-identified
trailing expression of every cell except the last, including multiline
expressions. Definitions and Markdown prose stay intact. Merge is one undo
operation; incomplete source is preserved rather than rewritten using guessed
expression boundaries.
Text editors keep ordinary copy/cut/paste and text-selection shortcuts. IME
composition does not trigger notebook shortcuts. In code editors Tab indents;
press Esc then Tab to move through controls.

Cell paste inserts after the selection without replacing it. Cells retain their
kind, source and explicit attributes, but receive fresh browser keys. Live
results, debug transcripts and separate saved snapshots are not copied. Explicit
IDs and definitions are preserved; if a pasted duplicate conflicts with another
cell, the normal Roc document diagnostics explain it. Paste and cut each form
one undo operation. A failed clipboard write does not delete cells.

The clipboard carries a versioned `application/x-roclet-cells+json` payload and
a plain-text envelope beginning `Roclet cells v1`, so browsers that discard custom
MIME data can still preserve cell boundaries. This is a clipboard format, not a
new notebook file format. Ordinary plain text pasted in cell selection mode
becomes one code cell; inside an editor it remains an ordinary text paste.

## Text editor and highlighting

CodeMirror 6 supplies selection, multiple cursors, input/IME handling and DOM
layout. All browser modules and MIT licenses are checked in under
`web/vendor/editor`; its lock records source archives, exact versions, SHA-512
integrity and file SHA-256 hashes. The 14 modules total about 1.17 MB of
uncompressed JavaScript. No Node, npm, bundler, CDN or extra runtime is required.

Normal Up/Down moves through lines and crosses to the previous cell's last line
or next cell's first line at an edge. This also opens Markdown for editing and
temporarily reveals collapsed cells. Their saved collapsed preference stays unchanged;
Escape, leaving the editor, or navigating to another cell hides the source again.
Use the cell menu’s Expand source action to keep it visible. Page Up/Down and Cmd+Up/Down move one editor viewport,
clamp to the first/last line, and cross cells only on the next press. They retain
CodeMirror's pixel-based horizontal goal through short lines; measured target
coordinates and its tab/grapheme column helper locate the destination. Horizontal
scrolling is used for long lines. Shift extends text selections within a cell;
multiple cursors remain within one editor.

Home and Cmd+Left go to the first nonblank character. Pressing them at or inside
the indentation goes to the start of the line; pressing again at column one goes
back to the indentation. Shift preserves the selection anchor.

- Alt/Option-click adds a cursor.
- Cmd/Ctrl+Alt+Up/Down adds a cursor above/below.
- Cmd/Ctrl+D selects the next occurrence; Cmd/Ctrl+Shift+L selects all occurrences.
- Alt+Shift-drag makes a rectangular selection.
- Typing, deletion and ordinary paste operate on the editor's selections.
- Cmd/Ctrl+/ toggles comments on the current or selected lines, including multiple
  cursors. Roc uses `#`; Markdown uses `<!-- … -->`.

The notebook's existing undo history owns text and structural changes together.
Cursor movement separates edit groups; browser-only cursor ranges are retained
with edit snapshots so multiple-cursor undo/redo restores their positions. These
ranges never enter `.roc` or `.md` exports.

Roc coloring uses the existing compiler syntax endpoint in a separate worker,
with one coalescing queue, a bounded cache and a timeout. It does not evaluate
code or interrupt the evaluation worker. UTF-8 compiler byte spans are converted
to UTF-16 editor positions, and results apply only to the exact current source
and cell kind. Old colors clear immediately on edits. Comments are recognized
only in gaps outside the compiler's tokens. Lezer provides incremental Markdown
source highlighting; Roc fences also receive compiler-based coloring. Rendered
Markdown still uses MD4C. Coloring failures leave the editor usable and do not
create or suppress compiler diagnostics.

## Boundaries between Roc and browser code

`core/Document.roc` accepts either source or an explicit draft of cell kinds,
source, attributes and saved outputs. The host obtains fresh Roc/MD4C syntax facts
for each cell. Roc alone selects output roots, lowers trailing expressions,
validates generated code, and encodes source. There is no second notebook parser
or naming implementation in JavaScript.

The browser owns DOM editing, temporary keys, undo, downloads, storage, and worker
lifecycle. `edit-model.mjs` coordinates those browser operations. Cell source
is retained independently from a derived document string, so an unfinished
expression in one cell cannot swallow later cells in notebook view.

`DocumentResponse.draft` is the editable representation returned by the core.
Inline output comments remain in code source and are not also copied into its
saved-output list. This prevents an import/edit cycle from duplicating snapshots.

## Evaluation and debug behavior

The `evaluate` document action passes the complete lowered user module to the
existing snapshot adapter, with explicit output roots. It excludes the script's
`display!` helper and generated `main!`. The adapter checks the whole module and
then evaluates each requested root. Run Cell still checks the whole module.
Manual mode defers execution until Run; dependency propagation still applies.
M4 now uses compiler-resolved dependencies to refresh dirty outputs, including
outputs in earlier cells, while retaining checked independent results. Run all
forces every output. See [M4](m4.md) for fingerprinting, error isolation, and
conservative invalidation boundaries.

Typing defers diagnostic presentation across the notebook, including downstream
errors, while automatic evaluation continues. Valid results update immediately;
incomplete code keeps the previous values gray without error panels or a red
status. Run, Escape, or leaving the editor reveals remaining diagnostics. Further
typing hides them again. Cursor movement and the editor's own search panel do not
end the edit. Manual-mode background checks and cell exit check the whole module
without evaluating its outputs; the next Run still refreshes the dirty notebook.
Pending checks/evaluations retain revision guards if editing resumes. Worker and
storage failures remain visible.

When the whole revision is already current, a successful cell rerun replaces only
that cell's output and debug transcript, preserving the others. This also works
when two cells reference each other's definitions, provided the definitions
are valid Roc (including recursive functions). Run All replaces the complete result
set. Compiler errors and Stop still invalidate current results; M4 runtime failures
can retain independent successful outputs. The notebook retains the previous output
and debug display in gray while typing, checking, running or showing an error.
A small spinner sits beside the old value; it rotates while an update is pending
or running, rests when updates are paused or blocked, and disappears when current.
Reduced-motion preferences disable its animation. Tooltips and accessible labels
explain that an old value is awaiting an update. Output DOM nodes update in place, so unchanged text keeps its selection and
layout. Retained displays follow browser cell keys when cells move, are discarded
on document switches or raw-source edits that may change cell boundaries, and
never enter evaluation, persistence or exports as current results. A successful
run with the output removed clears its old display.
`run` retains M1's ordinary generated-entry execution for CLI/script behavior.

A debug event carries its output root, model-cell index, and sequence number.
Messages from functions or dependencies appear beneath the root whose evaluation
produced them. The compiler does not yet expose originating debug source spans.
Each root is evaluated afresh, so a shared dependency may produce actual debug
messages during more than one root evaluation. M4 retains an unchanged root’s transcript alongside its checked output; evaluated
roots still produce fresh observations.

Events are buffered until a request finishes. A failed root publishes no value for
that root, while M4 preserves independent successful results. It retains the debug
messages that were collected,
visibly labeled as a failed run. Stop discards the pending synchronous worker;
it cannot retrieve messages that worker has not delivered. Superseded revisions
and terminated workers cannot publish results into the current draft.

Observation retention is limited to 1,000 events and 256 KiB per root, with a
64 KiB cap on each message/result and an explicit truncation event. Roclet stops
an evaluation after 15 seconds and pauses automatic execution. User Stop can
interrupt it earlier. The existing compiler memory/source limits still apply;
drafts are limited to 256 KiB and 500 cells.

## Markdown and imports

The vendored MD4C parser supplies typed block/span/text events for headings,
paragraphs, emphasis, lists, code, links, and tables. The browser creates a fixed
set of DOM elements. Raw HTML is text, unsafe URL schemes are inactive, and
images are explicit links rather than automatic network loads. No remote assets
or JavaScript execute merely because a document is opened.

Imported snapshots start unverified. They are never evaluation inputs and are
not labeled current. M2 preserves existing saved snapshots through conversion;
it does not automatically add new result/debug snapshots on download. Full
snapshot selection, attachment packaging, and offline installation belong to
later work. Generated-code conflicts remain available in source view and block
execution until resolved; Roclet never silently rewrites a handwritten main!.

## Current limits

Roclet uses locally vendored CodeMirror 6 for text editing, multiple cursors and
syntax highlighting. [M4](m4.md) adds checked-name completion, type hover, rename,
and selective output evaluation. Whole-module checking and per-root recompilation
remain deliberate compiler boundaries. Compiler errors block all outputs; runtime
errors are isolated. Rich output and typed widgets remain M5. Offline startup and
portable bundles are implemented in [M3](m3.md).

Browser storage is specific to this origin/profile and may be cleared or evicted.
It is recovery, not synchronization or a substitute for exported backups. Direct
writable-file connections and multi-tab coediting are not implemented. M3 adds
transactional stale-tab conflict detection and recovery copies.

## Verification

`zig build test` checks native document/evaluation contracts and produces complete
native-response fixtures. `/web/document-conformance.html` compares those against
WASM, including fresh workers. `/web/edit-conformance.html` tests revision races,
autosave ordering, real IndexedDB recovery, cell edits/movement/deletion/undo,
format switching, imported snapshots, Markdown rendering, evaluation failure,
output limits, and actual nontermination followed by Stop and restart.

Validation recorded in [m2-validation.json](m2-validation.json): 106 native
document contracts, 180 complete native/WASM document comparisons, 45 fresh-worker
document runs, 36 compiler parity cases, eight browser unit tests, and 13 Roclet
contracts passed. A downloaded Roc export also ran directly with the Roc compiler.

### UI validation

`/web/edit-ui-conformance.html` uses the actual Roclet UI with its own temporary
IndexedDB database. It checks seventeen interaction contracts, including selection
reversal, copy/cut/paste and undo, clipboard failure, Markdown editing/rendering
and undo with Auto-run off,
insertion around hidden generated code, keyboard focus, IME guards, and menu
bounds. Editor coverage includes page and cell transitions, tab/Unicode column
tracking, smart Home, multiple-cursor undo and stale highlighting. `?compact` runs the same checks in a 390px-wide iframe. Both variants and
the existing 13 Roclet contracts pass. Real browser keyboard copy/cut/paste was
also exercised separately. No compiler or language-core changes were needed.

The page has since grown to 56 contracts. Seven cover flat menus (format and
theme choices without nested selectors, inset hover rows, menus that fit the
viewport), keyboard help in Help and `?`, the Recent notebooks dialog, and the
Run/Stop slot whose bounds and focus stay put through saving, evaluation,
package waiting, cancellation, errors and timeouts. U1–U3 cover the
per-notebook layout: the title and run controls sit in the notebook's sticky
title bar above the first cell, the status bar stays at the bottom of the
notebook while its body scrolls and the page itself does not, and no element id
is duplicated while the primary notebook keeps the ids the other checks use.
`/web/dual-conformance.html` checks two notebooks side by side (19 contracts at
1280px, `?medium` 1000px and `?compact` 390px); see
[Compiler workspace](compiler-workspace.md#two-notebooks-side-by-side).

### Parser follow-up

The user pointed to [roc-parser PR #90](https://github.com/lukewilliamboswell/roc-parser/pull/90).
At the inspected head `7a871649a46e1eae1c5029296cf1a3b6f9dfe7c3`, its proposed
`RocSyntax` module exposes lossless tokens, UTF-8 byte spans, an indexed syntax
tree and recovery diagnostics. It remains a candidate if a standalone Roc lexer
is needed; current highlighting already consumes the pinned compiler’s tokens.
The PR is still a draft; binding/type analysis is outside its scope. Roclet's
current compiler-backed Roc parsing and MD4C rendering remain in place. Evaluate
compiler-version compatibility, recovery, WASM size and latency before adopting
a different Roc parser. Lezer Markdown is used only for source coloring in the
editor; it does not replace MD4C rendering or notebook-format parsing.

The M3 polish pass adds split/merge, cell find/replace, notebook search, diagnostic
source links, and full boundary-line selection for Shift page navigation. See
[M3 notes](m3.md) for commands and validation.
