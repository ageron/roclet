# M5 — rich output foundation

The first M5 step adds rich results. Typed inputs, widgets, CSV/JSON attachments,
and plots remain planned; this is not the complete M5 milestone.

Open **File → Rich outputs example** to create a separate example notebook.
The current draft is saved before switching. Everything in the example works offline
once **Prepare for offline use** has installed the updated release.

## Roc API

Use an unaliased `import Display` in the preamble or a code cell:

```roc
import Display

# %%
Display.markdown("## Results\nThe answer is **42**.")

# %%
Display.table(["Name", "Exact value"], [
    ["Large integer", "9007199254740993"],
    ["Decimal", "0.123456789012345678"],
])

# %%
Display.text("A plain-text result")
```

`Display.image(alt, mime, base64)` embeds PNG, JPEG, or WebP data. It does not
fetch remote URLs. SVG and raw HTML are not executable output formats.

Tables take a list of column labels and a list of rows, with strings in every
cell. Convert computed numbers with `Str.inspect(value)` or `value.to_str()`.
Numbers never pass through JavaScript's floating-point representation. Rich
values are ordinary pure Roc values, so definitions can construct and reuse them.

## Display and limits

- Tables render 50 rows per page, from at most 200 preview rows and 16 columns, with an aggregate
  8 KiB cell-text budget.
  Captions retain the total row/column counts. Long labels/cells are shortened to
  128 UTF-8 bytes; the preview clearly identifies its limits.
- Markdown uses the same MD4C parser and safe DOM renderer as notebook prose.
  Raw HTML remains text; unsafe link schemes are rejected.
- Images are embedded data, with no automatic network access. Browser previews
  accept at most 128 KiB of base64 data and supported MIME types.
- Plain-text alternatives are always available. The module bounds its text to
  16 KiB and Markdown to 16 KiB. Oversized images become a readable
  text result before encoding, avoiding excessive compiler allocation. The adapter bounds each rich wire payload to
  512 KiB. Truncated or invalid rich data retains the already computed text result.
- Renderer validation/errors do not turn a successful computation into a failed
  notebook run. Imported snapshots are validated and remain explicitly unverified.
- Editing keeps the previous rich DOM visible and dimmed until a new result
  arrives. Table pagination stays in place while that result remains unchanged.

These are display bounds, not a guarantee that arbitrarily large source programs or
input values fit the current interpreter memory budget.

The same bounds apply to exported previews. This step does not offer full-dataset
download, sorting, virtualized unbounded tables, or numeric column inference.

## Execution and portability

The bundled `package/Display.roc` defines an opaque nominal `Display` type with a custom
`to_inspect`. Existing generated `display!` calls therefore print readable text
when a notebook runs as a script; they do not emit a browser-specific envelope.

The snapshot adapter recognizes the compiler-checked nominal type only when the
notebook imports the trusted bundled module as `Display`. It binds each root once,
then obtains its inspected text and JSON-encoded structured representation.
It never detects rich values by parsing inspected Roc text. Ordinary strings,
records, local types called `Display`, and replacement modules remain ordinary
outputs. Import aliases currently receive plain-text rendering.

The JSON display protocol has `version: 1` and an explicit kind. Markdown parsing
adds structured rendering events before returning a notebook evaluation. Native
and WASM hosts share the protocol. Rich presentations are cached only under the
existing checked-revision/dependency rules; they are never fed back as Roc values.

For ordinary Roc execution outside Roclet, exported notebooks import the pinned
[Display package](../package/README.md). Roc fetches and caches it automatically;
Roclet supplies the same implementation offline. Bundles no longer need a sibling
`Display.roc`.

Bundles preserve rich output snapshots when **Include current results** is chosen.
Static reports include safe Markdown, images, and bounded tables with plain-text
alternatives. Interactive sites include the renderer, module, and example in their
verified offline release. Source-only files continue to use their existing output
comment formats; saving source does not silently embed rich snapshots or assets.

## Verification

`zig build test` includes rich output cases in the document contracts and generates
native/WASM parity fixtures. `/web/m5-conformance.html` exercises the real editor,
reactive updates, pagination, malformed/hostile values, image loading, plain-text
script execution, and bundle/report snapshots in an isolated notebook. Existing
editor and offline/sharing suites continue to cover the surrounding workflow.

## Mathematics in Markdown

Markdown cells and `Display.markdown(...)` support `$E = mc^2$` inline and
`$$ ... $$` display equations, including fractions, roots, Greek letters,
matrices, and `aligned` environments. Use blank lines around a display equation;
its contents may span consecutive lines. Code spans and fenced code are literal.
Escape a literal dollar with `\$`; ordinary `$5 and $10` currency stays text.
Roc string literals need their normal backslash escaping, for example:

```roc
Display.markdown("$\\frac{1}{2}$")
```

The existing MD4C parser recognizes equations. Locally vendored KaTeX 0.17.0
renders them with HTML and accessible MathML. No CDN, Node, npm, remote fonts,
or build-time package installation is required. The browser assets and license
are in `web/vendor/katex`; provenance and hashes are in its lock file.

Unfinished delimiters remain text. Invalid/unsupported TeX retains its original
source without a notebook error. This is KaTeX's supported TeX math subset,
not a full LaTeX document engine. Equations have an 8,192-character source limit, bounded
macro expansion and sizes, and isolated macros. HTML/network commands are
untrusted and cannot load images or inject user HTML.

Source saves and conversions preserve the equations. Reports embed the KaTeX
stylesheet and WOFF2 fonts and need no scripts or network access. Offline sites
include the same assets. The rich-output example now includes both inline and
display math. `/web/math-conformance.html` tests parsing, rendering, literal
contexts, fallback, unsafe input, conversion, rich results, and standalone reports.
