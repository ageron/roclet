# M3 — offline use and sharing

The offline and sharing implementation is available from Roclet's File menu.
All computation remains in local workers. The new features require no Node,
npm, bundler, package-manager installation, account, or external CDN.

## Using it

1. Open Roclet on HTTPS or localhost. Choose **File → Offline & storage →
   Prepare for offline use**. Preparation hashes every required application file,
   including the WASM compiler and the locally vendored editor.
2. Bookmark the Roclet URL, close Roclet, and reopen that same URL. You can then
   edit, run, recover drafts, and export with the network/server unavailable.
   **Ready offline** describes the verified installation at that origin/profile;
   it does not promise that the browser will never evict its storage.
3. **Keep browser storage** requests persistent storage where supported. The
   dialog reports whether the browser granted it and shows its storage estimate.
4. **File → Export & share** offers an editable Roclet bundle (`.roclet.zip`), a static HTML
   report, or an interactive `.site.zip`. These are local downloads. No upload
   or publication takes place.
5. Open `.roclet.zip` through **File → Open** in a compatible Roclet installation. Import
   verifies its member hashes and compiler identity before replacing a draft.
   It creates new browser identities and leaves automatic evaluation off.
   Imported result/debug snapshots are visibly unverified until recomputation.

A Roclet bundle contains the notebook, not another compiler/editor. A recipient
must have the matching Roclet installation. An interactive site includes both;
extract it and serve its directory on HTTPS or localhost. Its landing page offers
an editable copy, static report, and notebook download. Opening a published copy
never edits the publication itself. `report.html` also opens directly without a
server. Interactive `file://` startup is deliberately unsupported.

Source is always included in editable bundles and interactive sites. Reports
can hide code. Current result snapshots and this run's debug transcript are
separate explicit choices; debug is off by default. Existing saved-output
comments remain source content. Export captures a single revision and never
runs the notebook merely to fill in its outputs. A changed document cannot
silently export the preceding revision's results as current.

## Installation and updates

`zig build` generates `web/offline-release.json` and `web/offline-worker.mjs`.
The release version hashes the asset list, whose entries record byte lengths
and SHA-256 digests. The worker installs into an immutable versioned cache and
writes a completion marker only after every member is verified. Network,
integrity, and quota failures cannot replace the active release. Missing or
corrupt members invalidate readiness; explicit preparation can repair individual
files without deleting the remaining installation.

Updates wait for all tabs controlled by the old worker to close. There is no
`skipWaiting` or mid-session takeover. The old compiler and editor remain a
coherent set until the next navigation. Successful activation removes old release
caches for this scope; it never deletes the draft database. Notebook code and
arbitrary network responses are not added to application caches.

The browser may still check for a worker update while online. That check does
not mix runtime versions or switch an already open editor. Deployers must publish
the complete distribution together; a partially published update fails integrity
checks and leaves the preceding offline release active.

The runtime currently supports the pinned adapter's self-contained module
capabilities. User module resolution, data attachments, downloaded images, and
arbitrary external packages are not added by M3. Unsupported imports still
produce diagnostics; export does not invent or silently fetch dependencies.
The compiler's built-in modules and all required editor/runtime files are bundled.

## Recovery and concurrent tabs

IndexedDB writes commit transactionally. Each store instance tracks the last
version it loaded; save reads and compares that version inside the write
transaction. A stale tab fails visibly instead of replacing a newer draft.
Refreshing the recent-document list cannot reset that protection.

On failure the editor retains its local changes and continues to offer download.
**Save a recovery copy** appears in the File menu, creating a new local document
without overwriting the conflicting one. A failed/aborted transaction never says
“Saved.” Switching documents still requires saving the current draft first.
This is conflict protection, not collaborative editing or automatic merging.
Direct writable-file connections remain future work; downloads are separate
copies and never claim to have updated the file originally opened.

## Portable format

A bundle is ZIP32 with these members:

- `roclet.json`: schema/type, compiler commit and WASM hash, source filename,
  creation timestamp, and hashes/lengths of every other member.
- `notebook.roc` or `notebook.md`: the shared Roc core's source export.
- `document.json`: source/current-view information, cell kinds, source,
  attributes, and pre-existing saved outputs. No browser UUIDs, selections,
  cursor positions, file handles, or undo stack.
- Optional `results.json`: selected result/debug snapshots and their timestamp.

Source-only current views are parsed into current cell records for portability;
incomplete source is retained. Imports enforce the 256 KiB/500-cell notebook
bounds, an 8 MiB bundle limit, entry/hash checks, and compiler compatibility.
ZIP paths, duplicate entries, overlapping regions, invalid sizes, CRCs, and
expansion beyond declared sizes are checked. Exports use uncompressed STORE
entries. DEFLATE imports use the browser's `DecompressionStream` when available.
No archive member is executed or extracted to a filesystem during import.

The HTML report reuses the safe Markdown renderer, escapes source/results with
DOM text nodes, has no notebook scripts, and carries a restrictive CSP. An
interactive site includes the verified runtime assets and third-party notices,
plus the notebook bundle; that publication is added to its offline manifest.

## Packaging and headless use

```sh
zig build package
```

This verifies the compiler artifacts and produces:

- `zig-out/roclet.zip`: complete static browser distribution and a
  localhost server for the build host.
- `zig-out/roclet-headless.zip`: host-platform native runner, provenance manifest,
  instructions, and third-party notices.

The native runner already uses the same Roc document core and complete-module
snapshot evaluator as WASM:

```sh
./roclet run notebook.roc
./roclet run notebook.md
./roclet check notebook.roc
```

It emits structured JSON. Exit 0 is success; 1 is diagnostics/evaluation failure.
Use a job supervisor to bound native nontermination. The browser retains its
15-second timeout and worker Stop control. The current native distribution is
macOS ARM64; build for another host before using its native binaries. Public
redistribution still needs an explicit project license decision.

## Editor polish delivered alongside M3

- Shift+Page Down / Shift+Cmd+Down selects through the full final line when a page
  reaches the bottom. The corresponding upward selection reaches column one.
  Ordinary arrow motion retains the intended column.
- Cmd/Ctrl+Shift+Minus splits at the cursor. Shift+M in cell selection mode merges
  selected cells (or the next cell when one is selected). Both actions are also
  in the cell menu and are undoable. Mixed kinds or conflicting attributes are
  rejected without losing text.
- Cmd/Ctrl+F finds/replaces within a cell; Cmd/Ctrl+Shift+F searches the notebook
  and jumps to a matching line. Results are bounded to 100 matching lines.
- Diagnostic source links focus the correct editor/line and account for UTF-8
  diagnostic columns versus the editor's UTF-16 positions.

## Validation and release scope

The new `web/m3-conformance.html` exercises portable exports/imports, archive and
compiler integrity, independent recomputation, safe reports, complete site
assets, interrupted/cache-corrupt/quota-failed installs, aborted writes, stale-tab
conflicts, and recovery copies. Existing model and UI suites remain available.
See `m3-validation.json` for the observed runs and manual offline checks.

The available browser in this environment is the Codex in-app Chromium browser.
Firefox/WebKit and separate browser-profile runs remain release checks; a fresh
origin provides independent cache/storage isolation but is not a substitute for
engine/profile testing. No broad browser-support claim is made. PWA icon/install
promotion, direct file writes, attachment/module resolution, and richer app
layouts are outside this increment.
