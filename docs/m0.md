# M0 — Execution foundation

Status: **complete for the supported M0 subset**, verified on 2026-10-16.
The Zig tooling migration passes 5 Zig unit tests, 36 native conformance cases,
5 browser unit tests, and 36 native/WASM parity cases (including all 21 cell-order
permutations). Worker cancellation/restart/deletion and inline debug display also
pass. The original Node tooling has been removed.
See [validation](m0-validation.json) and [artifact identities](m0-artifacts.json).

## Chosen foundation

Roclet uses a versioned bridge over **whole-module checking and selected output
roots**, built from Roc commit `38a3029aa71b239c79b380adab7e90d4a848df96` with Zig
`0.17.0`. Both native and WASM artifacts come from the same pinned source and
bridge. The supplied Roc checkout is never edited.

This is a standalone execution prototype. It does not yet implement the Roc or
Markdown notebook parser, a Roclet editor, browser persistence, or a PWA.

The compiler accepts the concatenated cells as top-level application source.
Roclet adds a platform header and generated entrypoint, checks the whole module,
and requests outputs by ordinary binding name. It does not move user code into
a nominal-type namespace, parse Roc with regular expressions, scrape compiler
HTML/terminal output, or replay cells into a persistent REPL.

The embedding declares its runtime consumer before compile-time finalization
and consumes the retained lowering session. A structured callback captures
compile-time `dbg`; the runtime host captures `dbg`, expect failures, and crashes.
Both paths are necessary: observing runtime calls alone loses debug messages
from constants the compiler already evaluated. The retained-session path also
required one explicit `u64`→`usize` relocation-offset conversion in the pinned
compiler to build for wasm32; that fix is included in the overlay.

## Components

| Component | Implementation |
| --- | --- |
| Compiler bridge | `compiler-adapter/bridge.zig`, native process entrypoint, exact compiler overlay |
| Shared adapter | `snapshot.zig`: snapshot assembly, selected roots, metadata mapping, protocol validation on native/WASM |
| Roc core proof | `core/Revision.roc` (now `fixtures/modules/Revision.roc`): edit, input change, restart, and stale-token acceptance policy |
| CLI | Standalone native executable accepting the shared snapshot JSON protocol |
| Browser | Dedicated worker, Stop/restart, inline debug output, visible current result |
| Conformance | Zig unit/native tests, generated native references, browser JavaScript tests and WASM parity |

(Superseded: `snapshot.zig`, the `cells` request, `tests/native.zig` and the `fixtures/*.json` cell fixtures were retired; the same cases are `cells:` fixtures in `tests/documents.json`.)

The Roc policy module is exercised through both hosts. It is a portability proof;
the browser shell's small request gate is still JavaScript. Wiring the full Roc
document reducer into Roclet belongs to subsequent milestones.

## Conformance fixtures

Every permutation of the following cells must produce the same designated
values in the native and WASM hosts, including actual browser workers.

| Fixture | Permutations | Expected result |
| --- | ---: | --- |
| Forward references, two outputs | 6 | `15.0`, `15.0` |
| Per-definition dependencies that would form a false cell cycle | 2 | `3.0` |
| Lowered anonymous expression | 1 | `2.0` |
| Typed recursive factorial | 2 | `120` |
| Type alias, annotation, and value across cells | 6 | `15` |
| Explicit in-memory module import | 2 | `15` |
| User `dbg` inside a function | 2 | debug `5.0`, value `15.0` |
| **Total** | **21** | |

Additional tests cover malformed code, missing names, type errors, duplicate
bindings, deleted names, removed modules, Unicode source ranges, repeated debug
messages, unused definitions, runtime debug callbacks, failed outputs, request
ownership during asynchronous edits, and worker generation changes. The browser
suite also runs the Roc policy module and tests cancellation/restart/deletion.

The anonymous fixture contains the binding M1 will generate for `1 + 1`; this
milestone does not claim to implement anonymous-expression lowering.

## Reproduce

```sh
zig build -Droc-source=/path/to/roc
zig build test
zig build run -- fixtures/forward.json   # superseded; see tests/documents.json
zig build serve
```

Then open `http://127.0.0.1:4173/web/conformance.html` (superseded; see `web/document-conformance.html`) in a browser. It reports a
visible PASS/FAIL result, verifies the reference artifact manifest, and compares
native/WASM responses. `zig build test` does not automatically run the browser.
The test fixture order is independent of source order.

The build writes `artifacts/manifest.json` with the compiler commit, Zig version,
optimization modes, host architecture, bridge/overlay input hashes, and the
size and SHA-256 of both artifacts. The current WASM artifact is 15,292,566 bytes
and the macOS ARM64 native artifact is 50,790,520 bytes. An unchanged source build
reused the compiler cache in 954 ms during validation. A reference measurement and the
validation result are recorded beside this report. Native hashes are
platform-specific; reproducing the source/build lineage is the portability
contract, not promising identical binaries across operating systems.

## Boundaries for M1

- The API currently uses explicit JSON fixtures. Roc/Markdown cell parsing,
  generated source maps for trailing expressions, and conversion are M1 work.
- Evaluation recompiles the snapshot per output root. There is no persistent
  checked-revision handle, resolved dependency graph, selective recomputation,
  or structured value inspector. The fixture proves dependency *behavior*;
  it does not claim the API already exposes dependency edges.
- Value metadata covers simple top-level assignments. Destructuring output roots,
  app/platform conversion, associated-namespace metadata, effectful notebook
  roots, external package resolution, and arbitrary syntax conversion are not
  covered by M0's capability promise.
- The generated entrypoint and `echo!` names are reserved. Duplicate notebook
  value bindings are errors, even where Roc itself issues only a warning.
- Definition spans are UTF-8 bytes. Diagnostics use compiler-supplied display
  coordinates and rendered Markdown; multi-file byte-span normalization remains.
- Debug observations identify the requested output, but the compiler's event
  ABI does not identify the originating `dbg` expression. They are buffered;
  this prototype makes no live-streaming claim.
- The browser test serves its assets locally and executes Roc inside workers.
  Worker startup still loads JavaScript from the local server. Installable offline packaging, dependency caching,
  autosave, and sharing are later milestones.
