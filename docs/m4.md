# M4: selective recomputation and developer tooling

Roclet now checks each edited document and evaluates only affected output roots.
The engine computes the plan from the checked module's dependency graph; it
does not infer dependencies from cell order or text searches. A cell is still
an editing boundary, not an execution unit.

## Execution

- Auto-run checks a revision and evaluates changed definitions’ transitive outputs.
- With auto-run off, checking retains independent current outputs. Run cell also
  evaluates all dirty roots, plus the selected output. Run all forces every root.
- The graph (version 2) has a node per value definition (associated items as
  `Type.item`), per expectation, per local type declaration and per imported
  module (`module:<name>`). A definition or type fingerprint hashes the parser
  tokens it owns (tag and text, never offsets) and, for values, the inferred
  type; a definition owns its annotation. Comments, blank lines, whitespace and
  reordering change no fingerprint. A module node's fingerprint is the module's
  deep content identity, so a supplied module edit invalidates only the roots
  that reach it.
- Value edges are the compiler's strict-demand relation united with name
  references (including function bodies and recursive groups). Type edges come
  from annotations, constructions, patterns and method dispatch on a local
  nominal receiver; a type depends on its associated items and on definitions
  its field defaults read. Dispatch on a type-variable receiver depends on every
  local type.
- Added, removed, or rewired nodes are compared with the previous graph. An
  iterative dependency closure handles recursion without rejecting cell cycles.
- The context fingerprint covers the compiler identity, the app header's
  tokens, program tokens outside every node (imports, statements without a
  binder), the rich Display flag and the workspace files. A context change
  invalidates all roots. Module-wide invalidation (`scope: "module"`) remains
  only as a defensive fallback when the compiler's demand relation is missing
  or an import never resolved.
- Runtime failures are reported per output in Roclet; independent successful
  results remain current. Compiler errors still block the entire module. The
  compiler does not expose a safe partial-check boundary yet.

A successful check authorizes reuse of **presentation strings and transcripts**.
Those strings never become Roc input values. They live only in this Roclet session,
not IndexedDB, bundles, or a persistent compiler cache. A document/revision/request
check rejects late replies. A failing or cancelled check cannot promote old output.

The adapter still checks the whole program and compiles each evaluated root afresh.
It does **not** retain user compiler arenas, closures, checked modules, or heap
values between requests. Only the immutable Roc document/policy program is cached.
This is selective evaluation, not incremental compilation. (Superseded: the
interpreted document core and its scratch budgets were later removed; memory is now
described in `compiler-adapter/README.md`.)

## Optional tools

- Hover a checked name to see its inferred type.
- **Ctrl Space** offers checked notebook names and their types. While typing it
  can suggest names from the most recent successful check; suggestions are not
  proof that an incomplete document currently compiles.
- **F2** renames a top-level binding and compiler-resolved references across cells.
  The edit is type-checked before application and is one undo operation. Strings
  and comments stay unchanged. Existing local/global binders cannot be captured.
  Generated names and bindings used as record fields are currently refused;
  annotation shapes that leave an extra binding are refused too.
- **Cell menu → Dependencies & timing** explains the latest plan, lists direct
  dependencies, and shows elapsed worker time and evaluated/reused output counts.

These controls add no permanent cell header. There is no Node or npm dependency.

## Adapter contract

`analyze` returns checked definitions, source spans, references, binder names,
a `graph`, and a `plan`, without executing notebook roots. An `analyze` or
`evaluate` request may carry `reactivity: {force?, reset?}` to participate in
the engine-owned baseline. The core returns `plan.evaluate`, `plan.reused`,
changed definitions, and explanations. `evaluation.evaluated_roots` records
actual root invocations.

The engine, not the caller, keeps the previous graph and the observations of
each root's last successful evaluation, and returns complete `values`, `tests`
and `events` with `reused` flags (see `compiler-adapter/README.md`, "Reactive
baseline"). The baseline is a scheduling hint, not authenticated evidence or
execution state. It lives in engine memory only, is never accepted from a
request or an imported file, and does not survive a worker restart.

`isolateErrors: true` opts document requests into `partial` responses with
`root_errors` and successful `values`. The lower-level snapshot equivalent is
`isolate_errors`. Default headless/snapshot requests preserve atomic publication.
All semantic offsets are half-open UTF-8 byte spans; the notebook editor maps generated regions into normalized cell sources and
converts to UTF-16 only at its boundary. File-escape maps are reserved for
locations in the imported raw file.

## Validation and benchmark

`zig build test-m4` runs pinned workloads in `tests/m4-workloads.json` (28:
including forced roots, previously failed roots, a module context change, a
reused test, and the checked-graph workloads below), each as one
`roclet --bridge before selective full` sequence in a single engine. It checks
that the selective response's values, tests and events equal the clean full run
apart from `reused`, that `reused` matches `plan.reused`, the actual root
invocation lists and `workspaceCache.demand_union_fallbacks`, and writes the 84
complete responses for native/WASM parity; the browser replays them in order
through one worker, so it sees the same engine baseline.

`added-definition` now reuses both roots (nothing references the new
definition). The planned `destructuring-change` workload is not expressible: the
notebook frontend rejects a top-level binding that is not a plain name
(`unsupported-pattern`), so destructuring never reaches the analysis; its graph
nodes still list every binder (`binders`), and the planner resolves a
dependency on any binder.

The strict-demand cross-check: `ModuleEnv.topLevelDemandDependencies` alone is
not sufficient for reactivity. In `higher-order-callback`, `out_mapped` demands
`f` but not `a`, because strict demand does not follow a lambda passed to a
builtin; with demand-only edges, changing `a` would reuse a stale `[3, 4]`. The
analysis therefore keeps the union with name references permanently.
`workspaceCache.demand_union_fallbacks` counts, per non-function definition,
the definitions its united closure reaches and its strict-demand closure does
not: 1 for `higher-order-callback`, 0 for every other workload (asserted by
`tests/m4.zig`). Record field defaults are not followed by either relation
(`record-default-change`); the type node's edge to the definitions its
declaration reads covers them.

Open `web/m4-conformance.html` to replay those responses in WASM and exercise
manual reactivity, isolated runtime errors, a restarted worker without a
baseline, UTF-8 rename/collision/undo, and five
warm benchmark rounds changing one of eight independent outputs. The page reports
median selective/full worker time. Root counts and result equality are regression
assertions; wall-clock times are measurements, not machine-dependent pass gates.
The benchmark is also available independently at `web/m4-benchmark.html`. Cheap
outputs can show only a modest wall-clock improvement because document processing
and whole-module checking remain fixed costs; skipping roots is not a claim of
incremental compilation.

The Roclet UI suite also covers completion, rename dialogs, dependency menus and
retaining an independent output’s existing DOM node.

### Recorded validation (2026-10-19)

- `zig build test package`: passed; 36 native execution cases, 106 document
  contracts, 10 M4 workloads / 30 complete responses, and Zig unit checks.
- Browser parity: 36 execution + 180 document + 30 M4 responses matched native;
  45 fresh-worker document runs also passed.
- Roclet: 44 UI contracts passed in both wide and compact layouts; model checks
  covered persistence, revision races, failure handling and cancellation.
- Offline/sharing: all 11 M3 contracts passed; the distribution contains 54 verified
  assets and both Roclet and native-runner ZIPs were rebuilt.
- Five warm rounds of the eight-output arithmetic workload: median worker time
  **407 ms selective / 434 ms full**, with **1 evaluated / 7 reused** and identical
  results. These local measurements exclude cold startup and are illustrative.
